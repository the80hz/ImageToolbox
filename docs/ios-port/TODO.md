## Решения

| # | Решение | Статус | Почему |
|---|---|---|---|
| D1 | Нативный SwiftUI, без Kotlin Multiplatform и Compose Multiplatform | принято | Liquid Glass — SwiftUI API (`glassEffect`). Из KMP/Compose его нативно не использовать. Общего кода с Android мало: обработка портируется по алгоритмам |
| D2 | Минимальная iOS 26.0 | принято | Задача — iOS 26 и 27. Фолбэк на `Material` не нужен, Liquid Glass используется напрямую |
| D3 | Логика без UI в отдельном SPM-пакете `ios/ImageToolboxKit` | принято | Тестируется `swift test` без Xcode; подключён к app target |
| D4 | Тесты на Swift Testing (`import Testing`) для пакета | принято | XCTest нет в Command Line Tools. Для UI-тестов используется XCTest, его требует `XCUITest` |
| D5 | Форматирование и lint: `swift format` (Apple), `--strict` | принято | Идёт с тулчейном, новая зависимость не нужна |
| D6 | Минимальная версия iOS и SDK | решено | iOS 26.0 минимум, сборка на iOS 26.2 SDK из Xcode 26.3. iOS 27 SDK потребует macOS Tahoe, отдельное решение |
| D7 | Проект Xcode генерируется XcodeGen из `ios/project.yml` | принято | Текстовый источник истины, не правим `project.pbxproj` руками. Инструмент: `brew install xcodegen`, версия 2.46.0 |

## Окружение

- Mac: Apple silicon (arm64), macOS 15.8.1 (Sequoia). Xcode 26.3 (17C529), `xcode-select` указывает на `/Applications/Xcode.app`.
- SDK: iOS 26.2 (`iphonesimulator26.2`). Runtime симулятора: iOS 26.3 (23D8133).
- Симулятор: iPhone 17 Pro, UDID `71D45EE4-8E8C-4A7E-88AD-369068B6DE68`.
- [!] Apple Developer Program (платный, нужен для установки на физический iPhone и TestFlight).
  Симулятор работает без него. Решение за пользователем.
- Требования Xcode 27 по сторонним данным: macOS Tahoe 26.6+ и Apple silicon. Сверить на
  <https://developer.apple.com/xcode/system-requirements> перед обновлением системы.
- Известное ограничение инструмента симулятора в MCP: синтетические тапы не доходят до
  `NavigationLink` (касание приходит, но отпускание перехватывает системный жест). Свайпы работают.
  Поведение приложения проверяем через `xcodebuild test` (XCUITest). Баг приложения здесь не найден:
  переход в Base64 проходит в UI-тесте.

## Фаза 3. Большие фичи (L)

Состояние на 2026-10-10: `swift test` пакета — 1322 теста в 159 наборах на полном прогоне, зелёные, известных падений нет (CRC RAR проверяется, тест без `withKnownIssue`; тесты CBR, перенос слоя маркапа и `SmoothTraceTests` входят в прогон); `swift format lint --strict` по `ImageToolboxKit/Sources`, `ImageToolboxKit/Tests`, `ImageToolbox/Sources` и `ImageToolbox/UITests` чисто; сборка приложения проходит; смоук-тест `ToolsSmokeTests/testEveryToolOpensItsScreen` проходит на финальном коде (1 тест, 0 провалов, 733 с). Фаза L закрыта: все пункты `[x]`, решения записаны в самих пунктах и в «Решения фазы L».

Решения фазы L:
- GMIC (3 текстуры) не переносится: CeCILL-C несовместима с Apache-2.0 приложения.
- PGP-CFB, KEM (BIKE, SABER, SMAUGT), SM9 и PBEWITH не добавляются; ECB исключён.
- Бандл моделей фона: `u2netp` в бандле; `modnet` исключён из бандла (`project.yml`), экрана с ним нет; `RMBG-1.4` (CC BY-NC 4.0) и `YOLO11x-seg` (AGPL-3.0 в метаданных) не бандлятся до решения пользователя.
- PDF: длинная сторона при сжатии страниц по умолчанию 2000 px.
- JPEG XL с потерями: не портируется, ImageIO на iOS 26.3 не пишет JXL (проверено в симуляторе).
- TGS и WebM: не портируются, анимированные стикеры Telegram исключены из iOS.
- Лаборатория сжатия: внешние кодеки (MozJPEG, Jpegli, libimagequant, OxiPNG, VVC) не предлагаются.

- [x] Кривые тонов и осциллограф (`curves`, `lib/curves`). Подзадачи:
  - [x] RGB-кривые: монотонные (Fritsch–Carlson) для каждого канала и общая поверх них. Таблицы по 256 уровней на CPU, прозрачность сохраняется. Пакетный режим, отмена и повтор шагов, экспорт и «Сохранить в Файлы». Тесты: `CurvesTests` (12), UI: `testCurvesEditorAppearsAfterPick`
  - [x] Гистограмма исходника и результата (Swift Charts). Шкалы: цветной осциллограф по каналам (порог 0.55 от максимума, как в Android) и вектороскоп с группами оттенков и направляющими
  - [x] Пресеты `.itcurve` (JSON, как в Android), Lightroom XMP (чтение и запись), lrtemplate, ACV и zip-архивы (чтение, первый пресет по расширению, как в Android). Подключено: поворот и отражение, кроп, редактирование EXIF, водяные знаки, редактирование одного файла, шум Перлина, палитра, рамка скриншота, мозаика, обои, ASCII-арт, градиенты, код, вес, лимиты, нарезка, разбиение, склейка, стекинг, GIF, APNG, WebP, переименование (шаблон и экспорт), чексуммы, дубликаты, снежинки, изменение размера, цветовые утилиты. Логика проверена тестами пакета. На экране имена видны в переименовании: строки списка и экспорт используют одно имя. UI-тест `testBatchRenameShowsExportFileName` проверяет `photo_001.png`. Тест нашёл расхождение, которое исправлено: список показывал `.jpg`, а экспорт писал `.png`. В остальных инструментах имя видно только в системном шаринге, поэтому там оно на экране не проверяется.
- [x] Сохранение метаданных с опцией «не сохранять» (вариант Б): переключатель в настройках. Подключено в инструментах, которые строят результат из исходной картинки: изменение размера, вес, лимиты, кроп, поворот, редактирование одного файла, водяные знаки, нарезка, разбиение, мозаика, загрузка по URL, обои, сканер, рамка скриншота, WebP, переименование, пакетный экспорт. Склейка и стекинг берут метаданные первой картинки. PNG переносит EXIF, GPS и TIFF (проверено тестом). WebP переносит EXIF в чанк `EXIF` через libwebpmux (проверено тестом: ImageIO читает поле Make обратно). XMP и IPTC в WebP не пишутся. Удаление и редактирование EXIF работают с метаданными по своей задаче. Не применимо: GIF, APNG, градиенты, палитра, шум, код и обложка аудио (нет исходной картинки или нет EXIF в исходнике).
- [x] Отмена длинных операций: пакетные операции (кнопка «Отмена» в каждом пакете) и одиночные долгие операции GIF, APNG, мозаика и GIF сравнения. Отмена проверяется между кадрами и строками (`Task.isCancelled`), тесты пакета `CancellationTests`. Быстрые одиночные операции (изменение размера, кроп, поворот) отмены не имеют: они занимают доли секунды.
